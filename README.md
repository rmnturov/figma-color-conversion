# Преобразование цветов между кодом и Figma

Репозиторий содержит инструкции для переноса цветов между CSS, OKLCH и Figma, результаты исследования Display-P3 и методику повторной проверки.

Даты практических прогонов: **14 и 15 октября 2026 года**. Исследование выполнено в браузерном интерфейсе Figma, включая Dev Mode, диалог переменных и штатный экспорт и импорт JSON. Результаты относятся к проверенным образцам и датам прогонов.

## Проверенные выводы

- В HEX-поле переменной документа Display-P3 число задаёт P3-каналы. Для переноса OKLCH нужен HEX, собранный после преобразования в Display-P3.
- CSS-поле палитры переменной принимает `oklch(...)` и для проверенных цветов сохраняет более точные каналы, чем шестизначный HEX.
- Для одинаковой заливки Dev Mode выдаёт разные sRGB HEX-fallback при прямом цвете и при переменной. Результаты переменных исходных шести образцов совпали с численной моделью двойной конвертации P3 в sRGB с промежуточным округлением. Повторная проверка предсказаний на четырёх новых цветах также дала совпадение; три контрольных цвета проверены отдельно.
- P3-строка Dev Mode остаётся согласована с исходными каналами. Совпадение численной модели не доказывает устройство внутреннего кода Figma.
- Для проверенного цвета вне охвата P3 штатный ввод OKLCH обрезал P3-каналы до диапазона от 0 до 1.
- Формата просмотра OKLCH в меню Dev Mode нет. После ввода CSS временно отображалась исходная запись OKLCH; после обновления страницы вывод вернулся к HEX и Display-P3.

## Выполнение расчётов

Требования: Node.js 22 или выше и npm. Версия `colorjs.io` зафиксирована: `0.5.2`. Для `verify:replication:copies` дополнительно требуется Python 3; используются только модули стандартной библиотеки.

Чтобы выполнить расчёт и проверить сохранённые результаты:

1. Склонируйте репозиторий:

   ```sh
   git clone https://github.com/rmnturov/figma-color-conversion.git
   ```

2. Откройте каталог репозитория:

   ```sh
   cd figma-color-conversion
   ```

3. Установите зависимости:

   ```sh
   npm ci
   ```

4. Выполните нужную команду:

   ```sh
   npm run code:figma -- "oklch(32.6% 0.117 266)"
   npm run figma:code -- "#1D2D6B" --profile p3
   npm run verify
   npm run verify:copy
   npm run verify:variables
   npm run verify:replication
   npm run verify:replication:copies
   npm test
   npm run check:links
   ```

Первая команда возвращает `hexP3: "#1D2D6B"`. Вторая интерпретирует исходный HEX как Display-P3 и возвращает CSS, OKLCH и sRGB-представление.

`npm run verify` проверяет архив наблюдений, а не текущую Figma. Новый практический прогон выполняется по [методике исследования](docs/research-methodology.md).

В репозитории сохранён [штатный `.fig`](research/2026-10-14/figma/Codex-Color-P3-Transforms.fig). Обратный импорт подтвердил профиль Display-P3 и сохранность 110 узлов, 28 переменных и 32 заливок. [Реестр узлов](research/2026-10-14/node-registry.json) и [реестр тестов](research/2026-10-14/test-registry.json) связывают слои с исходными значениями и ожидаемыми результатами. Это копия тестового документа; исходный Overlays 4 полностью не архивирован.

## Границы применения

Проверены непрозрачные SOLID-заливки, локальные COLOR-переменные, цепочка из двух алиасов и штатный ввод OKLCH. Область проверки не включает градиенты, экспорт растровых изображений, сложные blend modes, библиотечную публикацию, Display-P3 на разных физических экранах и ввод альфа-канала переменной через HEX.

Утилиты сохраняют альфу в отдельном поле `opacity`. Альфа через HEX-поле UI отдельно не проверялась. Native JSON-импорт альфы проверен в прогоне от 15.10.2026.

Репозиторий создан приватным. Наличие ссылки на Figma не меняет права доступа к файлу.

Прогон от 15.10.2026 проверил штатный экспорт и импорт Variables. В P3-экспорте метка `srgb` сопровождает сохранённые P3-числа. Импорт RGB сохранил числа независимо от профиля; `components` имеют приоритет над HEX. Выявлено расхождение единиц HSL и изменение выходящих за диапазон значений после обновления. [Variables JSON](docs/variables-json.md) содержит данные и границы выводов. GitHub Actions проверяет архивы и расчёты; живые UI-опыты выполняются отдельно.
