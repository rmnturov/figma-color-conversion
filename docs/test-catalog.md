Каталог объединяет три отдельных прогона. Числа узлов, переменных и тестов относятся к своему прогону; исходные реестры не перезаписываются.

| Прогон | Область | Реестр |
| :--- | :--- | :--- |
| 14.10.2026, исходный | 32 прямоугольника: прямые и обратные опыты, эталоны и сохранение CSS-формы | [Тесты](../research/2026-10-14/test-registry.json), [110 узлов](../research/2026-10-14/node-registry.json) |
| 15.10.2026, Variables JSON | По 57 переменных и связанных слоёв в двух профилях; экспорт, импорт, приоритет полей и HSL | [Реестр](../research/2026-10-15/variables-json/test-registry.json), [описание опытов](variables-json.md) |
| 15.10.2026, повторная проверка после ревью | 21 наблюдение Dev Mode и 16 импортов; 74 узла двух документов, включая страницы | [37 тестов](../research/2026-10-15/replication-01/test-registry.json), [узлы](../research/2026-10-15/replication-01/node-registry.json) |

В исходном прогоне каждый из 32 прямоугольников связан с проверкой в `test-registry.json`. Запись содержит ID теста, ID и полный путь слоя, исходный цвет, ID переменной при наличии и ожидаемый результат. Число 32 описывает только исходный файл.

Страница — `0:1`. Прямые опыты находятся в FRAME `4:3` **P3 conversion experiments**, обратные — в FRAME `36:2` **OKLCH to P3 variable input**. Профиль Display-P3. Инструкция [восстановления `.fig`](local-figma-copy.md) объясняет замену fileKey в ссылках.

## Прямое преобразование

Для каждого цвета исследованы прямая заливка, примитивная переменная и роль с двумя локальными алиасами. ID теста имеет форму `FWD-<цвет>-<literal|variable|alias2>`. Значения колонок HEX получены через UI Dev Mode; форматирование сокращённого HEX нормализовано до шести цифр.

| Цвет | Literal ID | Variable ID | Alias2 ID | HEX прямой заливки | HEX переменной и роли |
| :--- | :--- | :--- | :--- | :--- | :--- |
| overlay | `4:11` | `4:14` | `4:17` | `#182E6F` | `#102F73` |
| light | `4:24` | `4:27` | `4:30` | `#BEDCFF` | `#B6DDFF` |
| red | `4:37` | `4:40` | `4:43` | `#FA0525` | `#FF0005` |
| green | `4:50` | `4:53` | `4:56` | `#00FF00` | `#00FF00` |
| gray | `4:63` | `4:66` | `4:69` | `#808080` | `#808080` |
| thread | `4:76` | `4:79` | `4:82` | `#FAB6B8` | `#FFB2B7` |

Коллекция — `VariableCollectionId:4:2`, режим — `4:0`, **P3 values**. Имена переменных: `primitive/<цвет>`, `semantic/<цвет>`, `role/<цвет>`. Роль ссылается на semantic, semantic — на primitive. Привязки по ID записаны в реестре и [состоянии Figma](../research/2026-10-14/evidence/figma-state.json).

Чтобы повторить все 18 проверок:

1. Для каждого цвета сверьте P3-каналы из [cases.json](../research/2026-10-14/cases.json) с прямой заливкой и разрешённой переменной.
2. Выберите прямоугольник по ID, проверьте его имя и откройте **Dev Mode → Code → CSS**.
3. Сохраните оба `background`: sRGB-fallback и `color(display-p3 ...)`, а также снимок слоя и панели.
4. Сравните HEX с таблицей, P3-строку — с исходными каналами с учётом четырёх знаков вывода.
5. Сравните примитив и роль: дополнительного преобразования на каждом алиасе в исходном прогоне не наблюдалось.
6. Сопоставьте fallback с численной моделью из [описания Dev Mode](dev-mode-fallback.md).

Доказательства: [19 наблюдений Dev Mode](../research/2026-10-14/evidence/devmode-observations.json), включая отдельный прямой CSS-ввод, и [расчёты](../research/2026-10-14/evidence/verified-calculations.json). Совпадение модели не подтверждает внутреннюю реализацию Figma.

## Обратный ввод

Коллекция — `VariableCollectionId:31:2`, режим — `31:0`, **Value** в локальной копии. ID теста имеет форму `INV-<имя переменной>`.

| Имя переменной | Слой ID | Переменная ID | Поле и ввод |
| :--- | :--- | :--- | :--- |
| overlay-p3-hex | `36:10` | `VariableID:31:3` | HEX `#1D2D6B` |
| overlay-srgb-hex | `36:13` | `VariableID:34:2` | HEX `#182E6F` |
| overlay-css-oklch | `36:16` | `VariableID:34:3` | CSS `oklch(32.6% 0.117 266)` |
| thread-p3-hex | `36:23` | `VariableID:34:4` | HEX `#F0B9B9` |
| thread-srgb-hex | `36:26` | `VariableID:34:5` | HEX `#FAB6B8` |
| thread-css-oklch | `36:29` | `VariableID:34:6` | CSS `oklch(84% 0.08 17)` |
| outside-p3-clipped | `36:36` | `VariableID:34:7` | HEX `#00CE00` |
| outside-srgb-hex | `36:39` | `VariableID:34:8` | HEX `#00D200` |
| outside-css-oklch | `36:42` | `VariableID:34:9` | CSS `oklch(70% 0.4 145)` |
| outside-p3-mapped | `36:45` | `VariableID:34:10` | HEX `#00C700` |

Чтобы повторить десять опытов ввода:

1. В восстановленной копии введите значение в ту же переменную через указанный UI-формат. Для CSS откройте палитру переменной, выберите **CSS** и подтвердите строку клавишей Enter.
2. Прочитайте `valuesByMode` и сохраните RGBA с ID переменной и режима.
3. Обновите страницу, повторно прочитайте значения и сравните их.
4. Для HEX сравните каналы с соответствующими байтами, делёнными на 255; допуск на канал — `2e-7`.
5. Для CSS внутри P3 сравните каналы с преобразованием исходного OKLCH в P3 с тем же допуском.
6. Для CSS вне P3 сравните с clipping: `[0, 0.8064367771148682, 0, 1]` в исходном UI-прогоне. У HEX `#00CE00` зелёный канал равен `206/255`, поэтому точные каналы CSS и HEX отличаются.
7. Вычислите ΔEOK относительно исходного OKLCH. Единица L — диапазон от 0 до 1; ΔEOK не умножается на 100.

HEX с суффиксом `srgb-hex` — контроль неправильной интерпретации: те же байты вставляются в P3-поле и задают другой цвет. `outside-p3-mapped` — контроль gamut mapping Color.js 0.5.2 с `method: "css"`; он отличается от проверенного штатного clipping Figma.

Доказательства: [RGBA после ввода](../research/2026-10-14/evidence/inverse-values.json), [сравнение ΔEOK](../research/2026-10-14/evidence/inverse-comparison.json), [UI после обновления](../research/2026-10-14/evidence/inverse-ui-persisted.txt). Точные ожидаемые RGBA каждого опыта находятся в реестре тестов.

Три прямых контрольных заливки: `REF-overlay`, ID `36:7`; `REF-thread`, ID `36:20`; `REF-outside`, ID `36:33`. Это расчётные эталоны, созданные через Plugin API. Вне P3 эталон использует clipping. Они служат сравнением результатов UI-ввода, а не отдельным доказательством работы UI.

При переменной заливки проверяйте разрешённое значение переменной для потребителя. В архиве `fill.color` отдельных образцов отличается от значения привязанной переменной: например, `outside-p3-clipped` содержит в paint зелёный канал около `0.8064367`, а переменная — `206/255`. Поле paint не заменяет `valuesByMode` и `resolveForConsumer`. Для чтения подготовлен [read-state.js](../scripts/figma/read-state.js).

## Сохранение CSS-формы после обновления

Тест `PERSIST-native-css`, слой `23:4`, **native-css-input**:

1. Введите `oklch(84% 0.08 17)` в CSS-поле прямой заливки.
2. Сохраните Dev Mode: в исходном опыте появился `oklch(84% 0.08 17deg)`.
3. Обновите страницу без промежуточного MCP-вызова.
4. Сохраните новый вывод: `#FAB6B8` и `color(display-p3 0.9417 0.7243 0.7259)`.
5. Отдельно прочитайте цветовые каналы и подтвердите сохранение цвета.

Ожидание касается текстового представления, а не потери цвета. Доказательство — [native-input-persistence.json](../research/2026-10-14/evidence/native-input-persistence.json). В локальном `.fig` уже сохранено итоговое состояние; для проверки временной формы нужно повторить ввод.

## Повторная проверка после ревью

В [прогоне replication-01](../research/2026-10-15/replication-01/README.md) предсказания зафиксированы до создания файлов Figma. Четыре новых цвета A–D и три контроля E–G созданы в P3-файле `2i0faqAmzqkPPD8Zsc0iMW`. Страница — `0:1`, общий FRAME — `2:3`. Входные float32-каналы, ID переменных, ожидаемый и наблюдённый HEX находятся в [реестре тестов](../research/2026-10-15/replication-01/test-registry.json).

| Образец | Literal, ID слоя | Variable, ID слоя | Alias2, ID слоя | HEX прямой заливки | HEX переменной и роли |
| :--- | :--- | :--- | :--- | :--- | :--- |
| A, с предварительным clipping P3 | `2:11` | `2:14` | `2:17` | `#DF00E4` | `#F400EC` |
| B | `2:24` | `2:27` | `2:30` | `#FEDF00` | `#FFDE00` |
| C | `2:37` | `2:40` | `2:43` | `#00EBEC` | `#00EFEE` |
| D | `2:50` | `2:53` | `2:56` | `#030920` | `#020922` |
| E, Red | `2:63` | `2:66` | `2:69` | `#FA0525` | `#FF0005` |
| F, Green | `2:76` | `2:79` | `2:82` | `#00FF00` | `#00FF00` |
| G, Gray | `2:89` | `2:92` | `2:95` | `#808080` | `#808080` |

ID самих COLOR-переменных записаны отдельно в реестре. Наблюдения на всех 21 слоях совпали с предсказаниями. Три варианта одного цвета не являются независимыми цветовыми образцами. Два чтения зафиксированы до сравнения; повторное чтение выполнено тем же агентом.

Парный импорт выполнен на переменной `color-space-probe`: `VariableID:2:97` в P3-файле и `VariableID:1:3` в sRGB-файле `xHj0Mhhmm4Vd7RsjyXuOZj`. На каждом целевом ID выполнены два цикла из четырёх импортов: пары `srgb` и `display-p3` для double и float32. Внутри пары менялся только `colorSpace`. Все восемь `srgb`-контролей обновили переменную; все восемь `display-p3`-записей вызвали ошибку и сохранили точный контрольный RGBA.

Каждая запись импорта связана с входным JSON, состоянием до импорта, UI-уведомлением, снимком и штатным повторным экспортом. [Реестр узлов](../research/2026-10-15/replication-01/node-registry.json) использует пару fileKey и nodeId: 73 узла P3-документа и одна страница sRGB-документа. В sRGB-файле образцы Dev Mode не создавались. [Локальные копии](local-figma-copy.md) сохранены отдельно от исходного файла.

## Автоматические проверки

| Команда | Что проверяет |
| :--- | :--- |
| `npm test` | Десять расчётных тестов из [colors.test.mjs](../test/colors.test.mjs) и [research-models.test.mjs](../test/research-models.test.mjs) |
| `npm run verify` | SHA-256 исходного архива, 19 CSS-наблюдений, модели 1–4 проходов и вариантов округления на шести цветах, два точных ввода, clipping и изменение формы после обновления |
| `npm run verify:copy` | SHA-256 `.fig`, сохранённое сопоставление 110 узлов, 28 переменных и 32 заливок, реестр тестов, профиль и два повторных CSS-наблюдения |
| `npm run verify:variables` | Архив первого JSON-прогона, поля и алиасы, пять непосредственных HSL-результатов в обоих профилях и их согласованность с кандидатной моделью, clipping после обновления |
| `npm run verify:replication` | Предрегистрация и контрольные суммы, два чтения 21 слоя, модели преобразования, все 16 импортов, реестры 37 тестов и 74 узлов |
| `npm run verify:replication:copies` | ZIP-контейнеры, CRC, SHA-256 и метаданные двух `.fig`-копий повторного прогона; требуется Python 3 |
| `npm run check:links` | Локальные ссылки Markdown |

Семь исходных расчётных тестов проверяют различие P3 HEX и sRGB HEX, обязательный профиль, округление каналов P3, перенос точных каналов без HEX, явный выбор clipping, отдельное хранение альфы и промежуточное байтовое округление. Три добавленных теста проверяют HSL-кандидат на пяти входах, варианты числа проходов и округления, различие double и float32 на Red. Все команды читают архивы или выполняют расчёты; они не управляют живой Figma и не доказывают её внутреннюю реализацию.

## Прозрачность и пределы проверки

Исходная структура группы Overlay проверялась в **Overlays 4**: один непрозрачный Fill внутри контейнера с opacity около `0.9`. Арифметика альфы и условия применения `color-mix` описаны [отдельно](opacity-and-color-mix.md). Этот документ и тест альфы утилиты не являются пиксельным сравнением Figma с браузером.

В сохранённый `.fig` не добавлены самостоятельные опыты градиентов, blend modes, растрового экспорта, библиотечных алиасов, ввода альфы через HEX и разных физических дисплеев. Для таких утверждений необходимы новые тесты.
