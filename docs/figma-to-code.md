# Перенос цвета из Figma в код

Штатный экспорт Variables требует проверки профиля: P3-каналы в опыте экспортированы с меткой `srgb`. [Export modes и интерпретация JSON](variables-json.md) дополняют чтение через Plugin API.

Для переноса цвета нужны исходные каналы и профиль документа. HEX без профиля не определяет один и тот же цвет в Figma и CSS.

В документе Display-P3 значение `#1D2D6B` обозначает P3-каналы `(29, 45, 107) / 255`. В CSS эта HEX-запись обозначает sRGB-каналы и другой цвет. Это различие объяснено в [документации OkColor](https://dokozero.design/en/projects/okcolor/#differences-in-the-hex-and-rgba-values).

## Источники значения

Источники для численной проверки:

- Значение переменной после разрешения алиасов в нужном режиме.
- Каналы SOLID-заливки и её привязка к переменной.
- Профиль файла, проверенный через UI.
- P3-строка Dev Mode как дополнительное представление цвета.

sRGB HEX-fallback переменной из Dev Mode требует отдельной проверки: в [прогоне от 14.10.2026](dev-mode-fallback.md) он отличается от преобразования исходных P3-каналов.

Скриншот подтверждает выбранный слой, профиль, режим или вывод интерфейса. Цвет пикселя скриншота не используется как численный источник.

## Получение цвета переменной

Чтобы собрать значение для преобразования:

1. Откройте целевой слой в Figma.
2. Проверьте профиль документа в **File color profile**.
3. Откройте сведения о переменной и проверьте коллекцию и режим.
4. Прочитайте привязку `paint.boundVariables.color` через Plugin API.
5. Разрешите цепочку `VARIABLE_ALIAS` до числового значения в нужном режиме.
6. Сохраните исходные `r`, `g`, `b` и `a` вместе с профилем, ключом файла, ID слоя и ID переменной.

`variable.resolveForConsumer(node)` разрешает значение с учётом потребителя. Для отчёта дополнительно сохраняется цепочка алиасов: одинаковое имя переменной в другой библиотеке или коллекции не доказывает совпадение значения.

Пример преобразования сохранённого RGBA:

```js
import { figmaChannelsToCode } from '../src/colors.mjs';

const result = figmaChannelsToCode(
    { r: 29 / 255, g: 45 / 255, b: 107 / 255, a: 1 },
    { profile: 'p3' }
);
```

Профиль задаётся явно: `p3` или `srgb`. Альфа хранится отдельно от RGB-каналов.

## Получение кода из P3 HEX

Чтобы преобразовать известный HEX из P3-документа:

1. Откройте каталог репозитория.
2. Выполните команду:

   ```sh
   npm run figma:code -- "#1D2D6B" --profile p3
   ```

Для проверенного цвета результат имеет следующие представления:

```css
color(display-p3 0.11372549 0.17647059 0.41960784)
oklch(32.58327% 0.1168928 266.16765)
```

Его sRGB HEX после округления — `#182E6F`. Все преобразованные sRGB-каналы находятся внутри диапазона от 0 до 1, поэтому обрезание на этом шаге ничего не меняет.

Если доступны исходные дробные каналы переменной, преобразование выполняется из них. Чтение шестизначного HEX добавляет округление и теряет часть точности.

## Политика для sRGB

Утилита возвращает:

| Поле | Содержание |
| :--- | :--- |
| `css` | Цвет в явно выбранном исходном пространстве |
| `oklch` | CSS-представление OKLCH |
| `oklchCoordinates` | Координаты OKLCH без округления для вывода |
| `srgb` | Преобразованные sRGB-каналы, включая значения вне диапазона |
| `inSRGB` | Принадлежность sRGB по диапазону каналов |
| `srgbClippedHex` | sRGB HEX после обрезания каналов и округления |
| `opacity` | Исходная альфа |

`srgbClippedHex` задаёт явную политику clipping для резервного значения. Это не универсальный алгоритм gamut mapping браузера и не повторение ошибочного fallback переменной Dev Mode.

## Профиль неизвестен

При неизвестном профиле одного цвета недостаточно для выбора интерпретации. Сопоставление выполняется на нескольких известных контрольных цветах в обеих гипотезах: sRGB и Display-P3. До подтверждения профиля преобразованные результаты обозначаются гипотезами.

Смена профиля с сохранением чисел и преобразование с сохранением внешнего вида — разные операции. [Документация Figma о профилях](https://help.figma.com/hc/en-us/articles/360039825114-Manage-color-profiles-in-design-files).
