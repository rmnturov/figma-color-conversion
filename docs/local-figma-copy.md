# Локальные копии Figma и восстановление

В репозитории сохранены пять штатных `.fig`-копий трёх прогонов. Обратный импорт выполнен для исходной копии от 14.10.2026. Четыре копии от 15.10.2026 проверены по ZIP-контейнерам, CRC и SHA-256; их обратный импорт не выполнялся.

| Прогон | Локальные файлы | Статус проверки |
| :--- | :--- | :--- |
| 14.10.2026, исходный | [Codex-Color-P3-Transforms.fig](../research/2026-10-14/figma/Codex-Color-P3-Transforms.fig) | Контейнер, контрольная сумма, обратный импорт, сопоставление структуры и два чтения Dev Mode |
| 15.10.2026, Variables JSON | [P3](../research/2026-10-15/variables-json/figma/Variables-JSON-Tests-P3.fig), [sRGB](../research/2026-10-15/variables-json/figma/Variables-JSON-Tests-sRGB.fig) | Контейнеры, CRC, метаданные и SHA-256; по 57 переменных и связанных слоёв в исходных тестовых документах |
| 15.10.2026, повторная проверка после ревью | [Replication-01-P3.fig](../research/2026-10-15/replication-01/figma/Replication-01-P3.fig), [Replication-01-sRGB.fig](../research/2026-10-15/replication-01/figma/Replication-01-sRGB.fig) | Контейнеры, CRC, метаданные и SHA-256; 73 узла и 22 переменные P3, одна страница и одна переменная sRGB в исходных документах |

Числа узлов и переменных новых прогонов получены чтением исходных файлов через Plugin API. Проверка контейнера `.fig` не декодирует `canvas.fig` и не заменяет чтение восстановленного документа. Дальнейшие разделы о выполненном восстановлении относятся к исходной копии; данные новых копий приведены в конце документа.

Исходный [файл `.fig`](../research/2026-10-14/figma/Codex-Color-P3-Transforms.fig) выгружен через **Main menu → File → Save local copy…**. Он содержит тестовый документ **Codex Color P3 Transforms**: 110 узлов, 32 прямоугольника, 28 COLOR-переменных и две коллекции.

Копия относится к воспроизводимым экспериментам этого исследования. Полный исходный документ **Overlays 4** в неё не входит. Его роль и структура описаны как контекст в [отчёте](../research/2026-10-14/README.md) и [документе о прозрачности](opacity-and-color-mix.md).

## Выполненная проверка восстановления

Файл `.fig` импортирован в Drafts через **Import from computer**. Получена [восстановленная копия](https://www.figma.com/design/6K0nZY2orMpyjCl6pxXaU0/Codex-Color-P3-Transforms?node-id=0-1) с новым fileKey `6K0nZY2orMpyjCl6pxXaU0`.

После импорта проверены:

- Все 110 ID узлов, их типы, имена и родительские ID.
- Все 28 ID переменных, scopes, коллекции, значения RGBA и ссылки алиасов — точное совпадение с исходным снимком.
- ID двух коллекций и двух режимов, их имена на момент выгрузки.
- Все 32 записи SOLID-заливок, их opacity и привязки к переменным.
- Display-P3 в меню **File color profile**, с сохранением [снимка](../research/2026-10-14/screenshots/restored-profile.jpg).
- Dev Mode у `overlay-literal`, ID `4:11`: `#182E6F`.
- Dev Mode у `overlay-variable`, ID `4:14`: `#102F73`.
- Одинаковая P3-строка двух последних образцов: `color(display-p3 0.1137 0.1765 0.4196)`.

[Исходная иерархия](../research/2026-10-14/evidence/original-node-hierarchy.json), [переменные при выгрузке](../research/2026-10-14/evidence/export-source-variables.json) и [состояние восстановленного файла](../research/2026-10-14/evidence/restored-file-state.json) позволяют повторить сопоставление. Остальная матрица Dev Mode и десять действий ввода переменных при восстановлении заново не выполнялись: они подтверждены исходным прогоном.

В раннем `figma-state.json` обратный режим называется **Mode 1**, а при выгрузке — **Value**. Его ID `31:0` и значения переменных сохранились. Для проверки имён режимов используется снимок при выгрузке; ранний архив не перезаписан.

## Повторное восстановление

1. Склонируйте репозиторий или скачайте `.fig` через кнопку **Download raw file** на GitHub. Если загружали репозиторий ZIP-архивом, сначала распакуйте его.
2. Выполните `npm ci`, затем `npm run verify` и `npm run verify:copy`.
3. В файловом браузере Figma откройте **Create new → Import → Import from computer**.
4. Выберите `Codex-Color-P3-Transforms.fig`, дождитесь завершения импорта и нажмите **Done**. Это штатный путь [импорта файлов Figma](https://help.figma.com/hc/en-us/articles/360041003114-Import-files-to-the-file-browser).
5. Запишите новый fileKey. Проверьте профиль Display-P3 через UI, не переключая профиль.
6. Снимите структуру и переменные через Plugin API. Найдите тесты в [каталоге](test-catalog.md) и [реестре](../research/2026-10-14/test-registry.json).
7. Сопоставьте ID и пути слоёв с [node-registry.json](../research/2026-10-14/node-registry.json). В нашем импорте внутренние ID сохранились; это результат опыта, а не гарантия будущих импортов.
8. Для ссылки на слой используйте новый fileKey и ID с заменой двоеточия на дефис: `https://www.figma.com/design/<fileKey>/<name>?node-id=4-14&m=dev`.
9. Повторите практические тесты по [методике](research-methodology.md), сохраняя новые результаты в отдельном каталоге.

Если ID изменились, сопоставляйте тип, полный путь и имя теста. В файле встречаются одинаковые имена у FRAME и RECTANGLE; одного имени недостаточно. Запишите соответствие старых и новых ID, затем проверьте режим и всю цепочку алиасов.

`npm run verify:copy` проверяет байты `.fig` и сохранённые данные обратного импорта. Команда не открывает живую Figma и не извлекает структуру из проприетарного `canvas.fig`. Для живой перепроверки нужен новый импорт и чтение через Figma.

Для снятия данных подготовлен [snapshot-file.js](../scripts/figma/snapshot-file.js). Функция `snapshotFile(figma, { pageId: '0:1', section })` вызывается отдельно для `hierarchy`, `variables` и `rectangles`; это уменьшает размер ответа каждого чтения. При исполнении через `use_figma` уберите `export` из объявления и добавьте `return await snapshotFile(figma, { pageId: '0:1', section: 'hierarchy' })`, затем повторите для двух других секций. Сохраните ответы до и после импорта и сравните их по ID, не по порядку массива. Шаблон адаптирован из выполненных чтений при упаковке репозитория; отдельный запуск экспортированного модуля не выполнялся.

`npm run verify:replication:copies` проверяет оба ZIP, CRC всех записей, SHA-256, метаданные и миниатюры; требуется Python 3. `npm run verify:replication` отдельно сопоставляет снимки состояния, 21 слой Dev Mode и 16 опытов импорта. Эти проверки не открывают Figma.

Для будущего восстановления нужен новый импорт `.fig`, подтверждение профиля и повторное чтение структуры, переменных, режимов и алиасов. Сохранность ID новых копий после импорта ещё не проверена. Файлы, метаданные и пределы проверки предыдущего JSON-прогона находятся в [отдельном отчёте Variables JSON](../research/2026-10-15/variables-json/README.md).
