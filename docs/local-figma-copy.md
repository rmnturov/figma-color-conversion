После импорта проверены:

- Все 110 ID узлов, их типы, имена и родительские ID.
- Все 28 ID переменных, scopes, коллекции, значения RGBA и ссылки алиасов — точное совпадение с исходным снимком.
- ID двух коллекций и двух режимов, их имена на момент выгрузки.
- Все 32 записи SOLID-заливок, их opacity и привязки к переменным.
- Display-P3 в меню **File color profile**, с сохранением [снимка](../research/2026-10-14/screenshots/restored-profile.jpg).
- Dev Mode у `overlay-literal`, ID `4:11`: `#182E6F`.
- Dev Mode у `overlay-variable`, ID `4:14`: `#102F73`.

[Исходная иерархия](../research/2026-10-14/evidence/original-node-hierarchy.json), [переменные при выгрузке](../research/2026-10-14/evidence/export-source-variables.json) и [состояние восстановленного файла](../research/2026-10-14/evidence/restored-file-state.json) позволяют повторить сопоставление. ## Повторное восстановление

1. Склонируйте репозиторий или скачайте `.fig` через кнопку **Download raw file** на GitHub. Если загружали репозиторий ZIP-архивом, сначала распакуйте его.
2. Выполните `npm ci`, затем `npm run verify` и `npm run verify:copy`.
3. В файловом браузере Figma откройте **Create new → Import → Import from computer**.
4. Выберите `Codex-Color-P3-Transforms.fig`, дождитесь завершения импорта и нажмите **Done**. Это штатный путь [импорта файлов Figma](https://help.figma.com/hc/en-us/articles/360041003114-Import-files-to-the-file-browser).
5. Запишите новый fileKey. Проверьте профиль Display-P3 через UI, не переключая профиль.
6. Снимите структуру и переменные через Plugin API. Найдите тесты в [каталоге](test-catalog.md) и [реестре](../research/2026-10-14/test-registry.json).
7. Сопоставьте ID и пути слоёв с [node-registry.json](../research/2026-10-14/node-registry.json). В нашем импорте внутренние ID сохранились; это результат опыта, а не гарантия будущих импортов.
8. Для ссылки на слой используйте новый fileKey и ID с заменой двоеточия на дефис: `https://www.figma.com/design/<fileKey>/<name>?node-id=4-14&m=dev`.
9. Повторите практические тесты по [методике](research-methodology.md), сохраняя новые результаты в отдельном каталоге.

Если ID изменились, сопоставляйте тип, полный путь и имя теста. В файле встречаются одинаковые имена у FRAME и RECTANGLE; одного имени недостаточно. Запишите соответствие старых и новых ID, затем проверьте режим и всю цепочку алиасов.

`npm run verify:copy` проверяет байты `.fig` и сохранённые данные обратного импорта. Команда не открывает живую Figma и не извлекает структуру из проприетарного `canvas.fig`. Для живой перепроверки нужен новый импорт и чтение через Figma.

Для снятия данных подготовлен [snapshot-file.js](../scripts/figma/snapshot-file.js). Функция `snapshotFile(figma, { pageId: '0:1', section })` вызывается отдельно для `hierarchy`, `variables` и `rectangles`; это уменьшает размер ответа каждого чтения. При исполнении через `use_figma` уберите `export` из объявления и добавьте `return await snapshotFile(figma, { pageId: '0:1', section: 'hierarchy' })`, затем повторите для двух других секций. Сохраните ответы до и после импорта и сравните их по ID, не по порядку массива. Шаблон адаптирован из выполненных чтений при упаковке репозитория; отдельный запуск экспортированного модуля не выполнялся.
